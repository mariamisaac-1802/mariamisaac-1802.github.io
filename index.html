Sleep Debt Medallion Data Warehouse

From a raw CSV to a SQL Server star schema that asks whether phone time before bed costs you sleep.

Objective

Build a repeatable pipeline from a raw behavioral dataset to reporting views. The warehouse answers whether more bedtime screen time means less sleep and more fatigue, whether a blue light filter or late caffeine changes how fast people fall asleep, and which apps, chronotypes, occupations and age groups show the worst sleep debt.

Method

  • Cleaned the data in Python: profiling, type fixes, deduplication, range validation and a quality log. Tested on a deliberately messy copy.
  • Staging as all-text so a load never fails. Bronze with TRY_CAST and an idempotent incremental upsert.
  • Silver with PK, FK, CHECK and UNIQUE constraints, business rules, and a transactional load that reports rejected rows.
  • Gold star-schema views and ten ready-to-run queries on KPIs, screen-time buckets, apps, chronotypes, caffeine and activity.

Outcomes

  • Row counts reconcile at 8,500 across all four layers.
  • Found that sleep-debt categories overlap in sleep hours, so the category is treated as a source attribute and not recomputed.
  • Found 314 users at the maximum fatigue score of 10, which points to a capped score.
  • Documented limits: no date column means no trend analysis, and results show association, not causation.

Data warehousing

SuperstoreDW, a T-SQL Medallion Warehouse

A raw sales CSV becomes a validated star schema, with an audit trail from source file to reporting view.

  • SQL Server
  • T-SQL
  • Stored Procedures
  • Medallion Architecture
  • Star Schema

4 dimensions1 fact viewCentral region extract

fact_sales ←
dim_customerdim_productdim_locationdim_date

Objective

Give analysts clean, typed, validated data to query instead of a raw file, with loads that can be rerun safely.

Method

  • Staging lands the file as text. Bronze appends with INSERT … EXCEPT, so a rerun adds nothing and changed rows keep their history.
  • Silver keeps the latest record per row, trims text, derives margin, shipping delay and a loss-making flag, and filters rows that break CHECK rules.
  • Gold views build surrogate keys and yyyyMMdd date keys.

Outcomes

  • BI-ready model with sample queries for sales by category, monthly trend, top customers and loss ratio.
  • Written naming conventions and design notes, including why persisted identity keys should replace view-based surrogate keys in production.
